Identified responsive design challenges with zoomed text settings
Identified responsive design challenges with zoomed text settings
This is a real and solvable problem — it's not just "that's how it is." Here's the breakdown:

Why it's happening When someone increases system font size or zoom, the sticky header and footer bars scale up with it but the middle content area doesn't get any extra room — so it gets squeezed into whatever's left, which can be tiny.

What can actually be fixed in the app

Use dvh instead of vh for height calculations 100dvh (dynamic viewport height) is more mobile-aware and accounts for browser chrome, address bars etc — more reliable than vh on mobile browsers
Cap the sticky bars with max-height Set a max-height on the top and bottom nav bars so they can't grow beyond a certain size even if text scales up — e.g. max-height: 60px with overflow: hidden
Use flex: 1; overflow-y: auto on the middle content area This tells the content section to take whatever space remains after the bars, rather than a fixed pixel height — so it always fills the gap regardless of bar size
font-size in rem not px throughout If any elements use fixed px sizing, they won't respect the user's system zoom. rem units scale with user settings more gracefully
Add a viewport meta tag check Ensure the app has <meta name="viewport" content="width=device-width, initial-scale=1"> — without user-scalable=no, which would block zoom entirely but is also bad accessibility practice
The honest caveat Extreme system zoom will always create some tension with fixed navigation — but the flex/dvh approach should make it significantly better for most zoom levels your husband would realistically use.

Here you go:

Please make the following updates to improve how the Sortii web app handles zoomed/large text settings on mobile devices:

1. Replace vh with dvh Anywhere the app uses 100vh for height calculations, replace with 100dvh (dynamic viewport height) so the layout responds correctly to mobile browser chrome and address bars.

2. Cap sticky header and footer bar height Add max-height: 60px and overflow: hidden to both the sticky top and bottom navigation bars so they cannot grow beyond a fixed size when a user has system font size or zoom increased.

3. Fix the middle content area to fill remaining space The main content area between the top and bottom bars should use flex: 1 and overflow-y: auto so it always fills whatever space remains regardless of how large the bars are. It should never be squeezed to a small fixed height.

4. Audit font sizes — use rem not px Check all font-size declarations across the app. Any that use fixed px values should be converted to rem so they scale gracefully with the user's system text size settings.

5. Check viewport meta tag Ensure the HTML includes <meta name="viewport" content="width=device-width, initial-scale=1">. Do not include user-scalable=no or maximum-scale=1 as these block user zoom and are bad for accessibility.

The goal is that a user with their phone zoom or text size increased should still see a usable layout with the full content area visible between the navigation bars.
