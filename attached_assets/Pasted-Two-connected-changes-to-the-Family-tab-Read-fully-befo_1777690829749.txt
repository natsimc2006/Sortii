CHANGE 2 — FIX SPLIT-EVENT PLAN LOGIC
──────────────────────────────────────
Find the sorting/resolution logic for the 
Family plan. Update it to handle two types 
of events:

TYPE A — requiresAdultPresence: true
  Treat as a single block. One adult must 
  cover full start to end time. 
  No splitting allowed.
  Conflict = no adult free for full duration.

TYPE B — requiresAdultPresence: false (default)
  Event can be split into two legs:
    Leg 1: drop-off (at start time)
    Leg 2: collect (at end time)
  
  Resolution logic for TYPE B:
  1. Check if original assigned adult 
     is free for FULL duration
     → If yes: assign as normal, no split needed
  2. If not free for full duration, check:
     a) Is original adult free at START time? 
        → They do drop-off
     b) Is another adult free at END time?
        → They do collect
     c) If both a and b are true → split resolved
     d) If only one is true → partial conflict, 
        flag it
     e) If neither → full conflict, escalate 
        to carpool crew if available

When a split is resolved, the plan table 
must show TWO rows for that event:
  [start time]  [adult A]  Drop off [child] 
                           at [location]
  [end time]    [adult B]  Collect [child] 
                           from [location]

Not one row. Two explicit rows.
