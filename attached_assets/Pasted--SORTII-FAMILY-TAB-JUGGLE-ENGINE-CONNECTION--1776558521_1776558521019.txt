SORTII — FAMILY TAB JUGGLE ENGINE CONNECTION
════════════════════════════════════════════

TASK
────
The Family tab currently stores and displays
events but does not run them through the
juggle solving engine. The logic files from
the original Juggle Solver exist in this
codebase but are not being called.

This prompt connects the existing engine
to the Family tab output.

Do not rebuild the UI. Do not rebuild the
logic files. Only wire them together.

════════════════════════════════════════════
STEP 1 — LOCATE THE EXISTING ENGINE FILES
════════════════════════════════════════════

Before writing any code, search the codebase
and identify the following:

1. The file containing the Anthropic API call
   for juggle solving — look for:
   - "claude-sonnet" or "claude-haiku"
   - "family weekend logistics solver"
   - The system prompt text
   - max_tokens setting
   Note the exact filename and location.

2. The file containing safeParseJuggleResponse
   or the JSON parsing logic.
   Note the exact filename and location.

3. The file containing the output rendering
   logic — look for:
   - "HERE'S THE SPLIT"
   - "THE PLAN" table
   - "NEEDS SORTING"
   - "WORTH KNOWING"
   - Visual timeline rendering
   Note the exact filename and location.

4. Any existing types or interfaces for:
   - Event objects
   - Adult/family member objects  
   - API response structure
   Note the exact filename and location.

DO NOT proceed to Step 2 until all four
files are located and confirmed to exist.

If any file is missing, note which one
and flag it — do not attempt to recreate
it without confirming first.

════════════════════════════════════════════

════════════════════════════════════════════

In the Family tab, trace and note:

A. Where family members are stored

   — which component/file shows the

This mapping tells us exactly where to

════════════════════════════════════════════
STEP 3 — MAP FAMILY DATA TO ENGINE FORMAT
════════════════════════════════════════════

The juggle engine expects this input format:

ADULTS FORMAT:
"Available adults:
[Name], can drive: [yes/no]
[Name], can drive: [yes/no]"

EVENTS FORMAT:
"Weekend events:
Child: [name]
Activity: [activity/event title]
Location: [location or 'not specified']
Day: [Saturday/Sunday/weekday]
Start: [time]
End: [time or 'not specified']
Assigned adult: [name or 'unassigned']
Notes: [any notes or 'none']"

Write a transformer function called
buildJugglePrompt() that:

- Takes the family members array
  (from wherever they are stored in Step 2A)
- Takes the events array
  (from wherever they are stored in Step 2B)
- Filters family members into adults 
  (role: 'adult' or 'Adult/driver') 
  and children (role: 'child' or 'Child')
- Maps each event's fields to the engine
  format — handle missing fields gracefully
  (use 'not specified' for optional fields)
- Returns a complete formatted string
  ready to send to the API

Place this function in a new file:
/utils/buildJugglePrompt.js
(or .ts if the project uses TypeScript)

════════════════════════════════════════════
STEP 4 — CREATE THE SOLVE TRIGGER
════════════════════════════════════════════

The engine needs a trigger point in the
Family tab. Add the following:

── THE TRIGGER BUTTON ────────────────────

In the Family tab, when events exist,
show a prominent button:

Text: "Sort the family juggle →"
Style: full width, teal #2A8F88, 
white text, bold, 50px height,
border radius 12px.

Position: below the events list,
above any bottom padding.

Only show this button when:
- At least 1 adult exists in family members
- At least 1 event exists this week

When no events exist yet:
Hide the button entirely.
The existing empty state UI handles this.

── ON BUTTON TAP ─────────────────────────

1. Set loading state to true
2. Show the processing overlay (see Step 5)
3. Call buildJugglePrompt() with current
   family members and events
4. Call the existing juggle API function
   with the built prompt
5. On success: navigate to results view
6. On failure: show retry state
7. Set loading state to false
