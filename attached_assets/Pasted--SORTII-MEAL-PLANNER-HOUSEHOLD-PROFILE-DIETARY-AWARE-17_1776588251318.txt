════════════════════════════════════════════
SORTII MEAL PLANNER — HOUSEHOLD PROFILE
+ DIETARY AWARENESS SYSTEM
════════════════════════════════════════════

TASK
────
Add a one-time household dietary profile
to the meal planner. This profile is set
once, remembered forever, and silently
shapes every weekly plan generated.

The user should never have to think about
it again after setup.

This is NOT a filter system the user
manages weekly. It is invisible household
intelligence — set once, works quietly.

North star check before every decision:
Does this remove a decision?
Does it feel like relief, not a tool?
Is the intelligence invisible?

PART 3 — PLAN GENERATION LOGIC
════════════════════════════════════════════

When generating a weekly plan, read
the household profile and apply the
following logic silently.

── A: DIETARY NEEDS FILTERING ────────────

Read 'sortii_household_profile'.dietary_needs.

For each dietary need selected, filter
the recipe library as follows:

VEGAN:
  Include only recipes tagged:
  dietary: includes "vegan"
  OR recipes where all ingredients have
  no animal products.
  
  If insufficient vegan recipes exist
  for the week (fewer than 7):
  Fill remaining slots with vegetarian
  recipes. Never use meat/dairy recipes.

VEGETARIAN:
  Include only recipes tagged:
  dietary: includes "vegetarian" OR "vegan"
  Exclude all meat and fish recipes.
  
  If insufficient vegetarian recipes:
  This should not happen given recipe
  library size, but if it does:
  Surface the empty state copy:
  "You've made this tricky 😅
   Try loosening a filter."

GLUTEN-FREE:
  Include only recipes tagged:
  dietary: includes "gluten-free"
  OR recipes with no gluten ingredients
  (flour, pasta, bread, soy sauce,
  barley, rye, wheat)

DAIRY-FREE:
  Include only recipes tagged:
  dietary: includes "dairy-free"
  OR recipes with no dairy ingredients
  (milk, cream, butter, cheese, yoghurt)

COMBINED (e.g. vegan + gluten-free):
  Apply all filters — recipe must pass
  all selected dietary criteria.
  If insufficient recipes, show:
  "Your dietary combination is quite
   specific — loosening one filter
   will give you more variety."

NONE SELECTED:
  No filtering by dietary need.
  All recipes available as normal.

── B: KIDS SITUATION WEIGHTING ───────────

Read 'sortii_household_profile'.kids_situation.

Use the existing kidFriendlyScore (0/1/2)
from kidFriendlyRules.ts for weighting.

"same" (everyone eats the same):
  No change to existing logic.
  Kid-friendly score not used unless
  user has also toggled the kid-friendly
  filter manually.

"simpler" (kids need simpler meals):
  Apply a weighting bias toward
  higher kidFriendlyScore recipes.
  
  Target distribution for the week:
  - 4-5 meals: kidFriendlyScore = 2
  - 1-2 meals: kidFriendlyScore = 1
  - 0 meals: kidFriendlyScore = 0
  
  This is a BIAS not a hard filter —
  adults still get variety, but the
  majority of the week is kid-accessible.
  
  Do NOT hide adult-leaning recipes
  entirely. Do not show only kid food.
  The intelligent balance is the point.

"separate" (kids eat separately):
  No filtering by kid score.
  Generate the adult plan as normal.
  Add a small note to the week header:
  "Plan is for adults — kids eating
   separately this week."
  Color: var(--text-muted) italic 13px.
  No other changes.

── C: INTERACTION BETWEEN FILTERS ────────

If user has BOTH dietary needs AND
kids_situation = "simpler":

Apply dietary filtering first.
Then apply kid-friendly weighting
within the filtered set.

Example: vegetarian household with
kids needing simpler meals → bias
toward vegetarian + kid-friendly recipes.

This combination works well as
vegetarian kid food (pasta, pizza,
frittata, quesadillas) is naturally
well-represented.

"For this meal:"

── SWAP MATCHING FUNCTION ────────────────

Create function:

getDietarySwapForIngredient(
  ingredient: string,
  dietaryNeed: string
): string | null

- Takes an ingredient name and a dietary need
- Checks DIETARY_SWAPS for a keyword match
- Returns the appropriate swap string
- Returns null if no swap exists or needed

── WHEN TO SHOW MODIFICATION vs EXCLUDE ──

SHOW modification note (not exclude) when:
- Recipe is mostly compatible but has
  1-2 adaptable ingredients
- The swap is simple (one ingredient)
- The meal format works for the dietary need

EXCLUDE the recipe entirely when:
- The core of the meal IS the ingredient
  (e.g. a beef stir fry for a vegan —
  the swap changes it completely)
- Multiple core ingredients need swapping
- No reasonable swap exists

HEURISTIC:
If more than 2 ingredients need swapping
to meet the dietary requirement →
exclude the recipe.
If 1-2 ingredients need swapping →
show with modification note.

════════════════════════════════════════════
PART 7 — ADD DIETARY TAGS TO RECIPE LIBRARY
════════════════════════════════════════════

The plan generation filtering in Part 3
requires recipes to have dietary tags.

Audit both recipe files:
- recipes_unified_au.json
- recipes_uk_clean.json

Add a "dietary" array field to each recipe.
Possible values: "vegan", "vegetarian",
"gluten-free", "dairy-free"

A recipe can have multiple tags.
Example:
"dietary": ["vegan", "gluten-free"]

TAGGING RULES:
──────────────

Tag as "vegan" if:
- No meat, fish, eggs, dairy, honey
- All ingredients are plant-based

Tag as "vegetarian" if:
- No meat or fish
- May contain eggs or dairy

Tag as "gluten-free" if:
- No wheat, barley, rye, regular flour,
  regular pasta, regular bread,
  regular soy sauce, regular breadcrumbs

Tag as "dairy-free" if:
- No milk, cream, butter, cheese,
  yoghurt, sour cream, cream cheese

Tag with empty array [] if none apply.

After tagging, report:
- How many recipes are vegan
- How many are vegetarian (including vegan)
- How many are gluten-free
- How many are dairy-free
- How many have no dietary tags

If fewer than 14 vegan recipes exist
(enough for 2 weeks):
Flag this as a gap — do not add
recipes now, just flag for future
recipe library expansion.
