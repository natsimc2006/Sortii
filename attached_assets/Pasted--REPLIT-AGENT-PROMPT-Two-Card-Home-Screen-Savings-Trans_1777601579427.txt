## STEP 1 — DATE UTILITY FUNCTIONS

Create or update `utils/weekUtils.ts` with the following functions. Do not modify any existing functions in this file if they already exist — append only.

```ts
// Returns 0=Monday through 6=Sunday (remaps JS Sunday from 0 → 6)
export function getTodayDayIndex(): number {
  const day = new Date().getDay();
  return day === 0 ? 6 : day - 1;
}

// Thu=3, Fri=4, Sat=5, Sun=6 are the "shop window"
export function isShopWindow(): boolean {
  return getTodayDayIndex() >= 3;
}

// Returns Monday–Sunday Date range for the current calendar week
export function getThisWeekRange(): { start: Date; end: Date } {
  const today = new Date();
  const dayIdx = getTodayDayIndex();
  const monday = new Date(today);
  monday.setDate(today.getDate() - dayIdx);
  monday.setHours(0, 0, 0, 0);
  const sunday = new Date(monday);
  sunday.setDate(monday.getDate() + 6);
  sunday.setHours(23, 59, 59, 999);
  return { start: monday, end: sunday };
}

// Returns Monday–Sunday Date range for next calendar week
export function getNextWeekRange(): { start: Date; end: Date } {
  const { start } = getThisWeekRange();
  const nextMonday = new Date(start);
  nextMonday.setDate(start.getDate() + 7);
  const nextSunday = new Date(nextMonday);
  nextSunday.setDate(nextMonday.getDate() + 6);
  nextSunday.setHours(23, 59, 59, 999);
  return { start: nextMonday, end: nextSunday };
}

// Key format for storing next week's plan — e.g. "plan_2025-05-05"
export function getNextWeekKey(): string {
  const { start } = getNextWeekRange();
  return `plan_${start.toISOString().split('T')[0]}`;
}
```

## STEP 6 — SAVINGS TRANSPARENCY FIX (Money / Budget page)

This is a separate fix on the money or budget tab. Do not touch the home screen components for this step.

### Current problem
The app shows a saving amount (e.g. "You're saving $X on dinner") but does not explain how this figure is calculated. Users don't understand where it comes from.

### Fix required

Find where the savings figure is calculated and displayed. Update the display to include a transparent breakdown note directly beneath the saving amount.

The calculation logic is:
```
savingsAmount = userGroceryBudget - weeklyMealPlanCost
baselineDinnerSpend = userGroceryBudget * 0.65
```

Where `0.65` represents the industry average: 65% of a household grocery bill goes on dinner.

Display format — directly below the saving amount figure, add this note in small muted text:

```
Based on your $[userGroceryBudget]/wk grocery budget.
Dinner is typically 65% of that (~$[baselineDinnerSpend]/wk).
Your plan this week costs $[weeklyMealPlanCost].
```

Style for the note:
- Font size: 12px
- Colour: muted (#888888)
- Line height: 1.5
- Italic style preferred
- Positioned directly beneath the savings figure, above any CTA buttons
- Do NOT use the word "approximately" — use "~" symbol only
- Do NOT use "based on average" — use "typically"

### Safety rules
- If `userGroceryBudget` is 0, null, or undefined → suppress the note entirely, show nothing
- If `weeklyMealPlanCost` is 0, null, or undefined → suppress the note entirely
- If `baselineDinnerSpend` would be lower than `weeklyMealPlanCost` → suppress the saving claim and note entirely; show no negative saving
- Round all dollar figures to nearest whole dollar (no cents)
- Currency symbol should match user locale: $ for AU, £ for UK

Confirm: savings note renders correctly when budget and meal cost are both set, and suppresses correctly when either is missing.
